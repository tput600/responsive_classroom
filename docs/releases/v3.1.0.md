# Responsive Classroom v3.1.0

## One desktop download

Download `ResponsiveClassroom-AllPlatforms-v3.1.0.zip` and its matching `.zip.sha256`.
The archive contains:

- `Windows/ResponsiveClassroom.exe` and the complete Windows x64 `_internal` runtime.
- `macOS/ResponsiveClassroom.app`, one universal2 app for Apple Silicon arm64 and Intel x86_64 on macOS 14 or later.
- Offline model resources, the included media, original licenses and third-party notices, platform manifests, and an all-platform integrity manifest.

Extract the entire archive. Windows users must keep `_internal` beside the EXE.
Mac users should extract with Archive Utility or `ditto` to preserve executable
permissions and framework symlinks. Keep the whole app bundle intact. A separate
Python installation is not required.

## Settings and audio updates

Settings now use section-level editing with stable drafts. WLED panel setup
combines the IP field, Add, and Auto-search controls; a network selector appears
only when multiple eligible subnets exist.

Audio handling improves recovery from stale, dropped, or overloaded capture and
avoids duplicate endpoint handling. On the same 22 synthetic fixtures, median
raw-VAD onset changed from 327 ms to 191 ms and tail from 473 ms to 313 ms. These
are detector-level results: overall ASR command accuracy remained 7/18 and
measured command latencies did not improve. See the [audio benchmark report](https://github.com/tput600/responsive_classroom/blob/v3.1.0/docs/benchmarks/audio-v3.1.0.md)
for the full method and limitations. This is not a claim of reliable
classification of all natural human and environmental sounds. Speech guarding
and timeout behavior still need real classroom validation.

## Validation required for publication

Publication is gated on one successful `unified-desktop.yml` run of the exact
approved `main` commit, with the Windows build, Mac universal2 build, native
arm64 test, native x86_64 test, and final assembly jobs all successful. The Mac
native tests must reference the same original Mac archive SHA-256 and pass the
frozen offline-model and WebEngine UI smoke checks. Assembly checks the complete
Windows and Mac manifests, bytes, executable permissions, and symlinks.

The selected build run URL, commit, platform input hashes, and native summaries
are retained in `desktop_manifest.json`. The release publisher verifies the
immutable GitHub artifact download digest, the final ZIP checksum and contents,
and both uploaded release asset digests before making the draft the latest
release. These are automated integrity and smoke-test gates, not a claim that
all hardware and classroom workflows have been accepted.

## Known limits

- Manual Finder launch, Gatekeeper behavior, microphone/local-network TCC consent,
  real microphone and speaker operation, and physical WLED interaction are not
  established by the CI tests. They still need validation on actual systems.
- The Mac app uses ad-hoc signing. It has no Apple Developer ID signature and is
  not notarized. This release does not guarantee Gatekeeper acceptance. If the
  system blocks it, stop and obtain a properly signed/notarized build from the
  maintainer. Do not disable Gatekeeper, Chromium's sandbox, or other security
  protections.
- Redistribution rights for the included Blue Danube recording have not been
  independently verified. Attribution is not a recording license. The project's
  MIT license does not grant rights to third-party recordings; publication does
  not resolve that issue. Keep the original media attribution and license notices.

## Maintainer release procedure

1. Review and merge the final source, release wording, notes, and publication
   workflow. Confirm `classroom_resources.VERSION` is `3.1.0`.
2. Run `unified-desktop.yml` on `main` or `codex/unified-desktop-package`. Wait for
   all required jobs to pass, and ensure the tested SHA exactly equals the current
   approved `main` tip before publication. An older branch candidate, unrelated
   branch, or differently named candidate ZIP is intentionally rejected. Do not rewrite the ZIP during publication.
3. Manually dispatch `publish-unified.yml` from `main` with that exact
   `candidate_run_id`. The current main tip, publisher checkout, and candidate
   commit must still agree. The publication workflow uses the existing
   `responsive_classroom` environment and any repository-configured approval
   protections; it does not configure or bypass them.
4. If upload or verification fails, inspect the unpublished draft. Only after
   confirming its exact numeric release ID, rerun the same manual workflow with
   `draft_release_id`. Recovery downloads and revalidates the same artifact,
   requires the original complete two-asset set and matching digests, and only
   promotes that verified draft. It never repairs, overwrites, or deletes assets.
   A partial draft requires separate reviewed remediation.

When a manual-dispatch client is unavailable, a separately reviewed one-time
bootstrap can use `codex/publish-v3.1.0`. Its sole commit must directly follow the
approved main SHA and modify only `.github/workflows/publish-unified.yml`; that
workflow must pin `APPROVED_RELEASE_COMMIT` and `APPROVED_CANDIDATE_RUN_ID` and
checkout the approved source SHA. The helper validates the branch tip, parent,
changed-file scope, both pins, and all ordinary run/artifact/native gates. The
normal main workflow remains manual-only. This is not a general push publisher.

The script also provides a read-only `verify` command with `--candidate-run-id`,
`--commit`, and a new `--artifacts` directory. It runs under the same approved publication
workflow context and does not create or edit releases. `prepare` performs only
run/provenance checks and emits the immutable artifact ID and digest to `--output`.
The publisher is fixed to `v3.1.0`; it never mutates `v3.0.3` or another release.
GitHub-generated source archives are separate from the two uploaded assets.
