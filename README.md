# responsive classroom 3.2.0

[English](README.en.md) · 繁體中文

本手冊說明 Web UI 的燈板連線、收音校準、音量調適、語音指令、計時與音源設定，以及本地／雲端的開發與發佈方式。一般使用者下載完整可攜版後，直接開啟程式，不必安裝 Python。

介面可按工具列的「EN」切換英文，按「中文」切回繁體中文；操作手冊可用上方連結切換語言。

原始碼：[tput600/responsive_classroom](https://github.com/tput600/responsive_classroom)；可執行套件：[GitHub Releases](https://github.com/tput600/responsive_classroom/releases)。請下載 Release 的可攜 ZIP；GitHub 的「Download ZIP」只有原始碼，不能直接啟動。

## 1. 使用前準備與啟動

先在 WLED 完成控制板燒錄、Wi-Fi 連線與 8×8（64 顆 LED）設定，並確認電腦和燈板位於可互通的區域網路。程式不負責初次燒錄或 Wi-Fi 配網。校園或公共 Wi-Fi 若隔離裝置，請改用允許彼此連線的網路。

下載 `ResponsiveClassroom-Portable-windows-x64-v3.2.0.zip` 並完整解壓縮；不需要安裝 Python。開啟 `ResponsiveClassroom.exe`，保留旁邊完整的 `_internal` 與其他檔案，不能只複製 EXE。v3.1.1 起只維護 Windows x64 可攜版；舊 Mac 封裝不再隨本版更新。

離線模型、Web UI、字型、播放元件與收音依賴已包含在完整套件中；語音辨識在本機執行。Release 的 SHA-256 檢查檔用於核對下載完整性，不是程式碼簽章。

## 2. 連線與校正燈板

在「連線與收音」頁輸入自己的燈板 IP，按「加入燈板」。也可在同一區按「自動搜尋」，勾選找到的裝置後一次「加入所選燈板」。只有一個可用網段時直接搜尋；多個網段時才展開選擇，不會自動掃描所有網路。搜尋只涵蓋所選的本機網段；跨網段時請手動輸入 IP。下方每一列的「同步」勾選決定是否將畫面送到該燈板，最多八塊。介面提供的是格式範例，不是可直接套用的裝置地址。

連線狀態先顯示等待確認，收到裝置回報後才顯示「已確認接收」。在「燈板方向」選擇裝置，調整旋轉、蛇形排列及水平／垂直鏡像，再按「儲存」。若畫面呈現散點或方向顛倒，先核對這些設定，避免 WLED 與程式重複排列像素。移除燈板只會移除程式中的裝置設定。

## 3. 選擇麥克風與安靜校準

在新電腦上，先到 Windows「設定 → 隱私權與安全性 → 麥克風」，開啟麥克風存取及「讓桌面應用程式存取您的麥克風」。程式會在舊電腦儲存的裝置不存在時改用這台電腦的系統預設輸入；也可在「連線與收音」頁重新整理並選擇裝置。確認即時音量會變化，再固定麥克風位置與系統輸入增益，在教室安靜時按「安靜校準 12 秒」；前 2 秒不計入。說話、削波、收音中斷或環境波動過大都可能使校準失敗。失敗時原本有效的基線會保留。

顯示值是麥克風輸入的 dBFS，不是校準過的環境 dBA。音量分類依目前讀值相對於安靜基線的差值判斷；基線固定，不會隨持續吵鬧自動上移。更換麥克風、改變輸入增益或移到另一間教室後，重新校準。

## 4. 音量門檻與調適方法

「請注意」適合聽講，「討論」允許較大的交談音量。兩種模式各自有「漸活躍」與「活躍」門檻，以及恢復門檻：

| 狀態門檻（高於安靜基線） | 請注意 | 討論 |
|---|---:|---:|
| 進入漸活躍 | +8 dB | +12 dB |
| 進入活躍 | +15 dB | +19 dB |
| 漸活躍時恢復平穩 | 低於 +5 dB | 低於 +9 dB |
| 活躍時降低至漸活躍 | 低於 +14 dB | 低於 +17 dB |

例如安靜基線為 −55 dBFS、目前輸入為 −37 dBFS，差值是 +18 dB。請注意已達到「活躍」門檻；討論則已進入「漸活躍」，尚未達 +19 dB 的活躍門檻。這說明同一音量會依目前課堂活動顯示不同節奏。

建議先完成安靜校準，再觀察老師講解與學生討論時的實際讀值。太容易進入較高狀態時，每次將該狀態的進入門檻提高約 2 dB；很難觸發時，每次降低約 2 dB。一次只改一項、觀察一輪活動後再決定下一步。討論門檻不可低於請注意門檻。若燈光在相鄰狀態間來回，保留進入與退出門檻的距離，並適度增加持續時間；不要以大幅提高門檻掩蓋麥克風位置或校準問題。

預設判斷時間為：漸活躍需持續 0.45 秒、活躍需持續 0.75 秒、狀態恢復需穩定 1.2 秒；音量平滑 300 ms。短促碰撞聲不會只憑瞬間峰值改變狀態。進階欄位可按箭頭展開，調整兩種狀態的進入時間、共用恢復時間、平滑時間及各自恢復門檻。

「麥克風與音量」區右側的「儲存設定」會一起保存音量門檻、觸發詞及辨識修正。全部欄位通過驗證才會一次保存，錯誤別名或門檻不會只儲存一半。計時與播放設定分別使用「儲存計時」及「儲存音源設定」。數字欄位請以鍵盤輸入；滑鼠滾輪不會更改參數。

## 5. 七種課堂模式與十二種燈效

課堂頁左側顯示燈板、麥克風與語音狀態，中間顯示目前模式、倒數與 8×8 畫面，右側提供手動切換。手動選擇基礎模式會立即生效，也會優先於尚未完成的舊語音結果。

預覽與實板共用同一份像素畫面；每塊板再依自己的方向設定排列。亮度上限 30%，一般模式以 1.4 秒平滑轉換，音量分級以 3 秒平滑轉換。這些燈光是背景節奏，不使用急閃或警告圖示；預覽正在變化仍須搭配板子的接收狀態及實際畫面確認。

| 模式／情境 | 燈色與畫面 | 動態 |
|---|---|---|
| 待機 | 暖金柔光 | 緩慢漫遊與呼吸 |
| 請注意・平穩 | 暖綠中央光面 | 平順呼吸 |
| 請注意・漸活躍 | 橘色橫向光帶 | 緩慢流動 |
| 請注意・活躍 | 珊瑚色直向曲線波 | 緩慢移動 |
| 討論・平穩 | 蜂蜜金雙星與短拖尾 | 在左右兩側繞行接力，10 秒一圈 |
| 討論・漸活躍 | 青綠四臂風車 | 12 秒平順旋轉 |
| 討論・活躍 | 玫瑰色雙星環流 | 沿矩陣外緣繞行，12 秒一圈 |
| 提問 | 紫色開口圓弧 | 每 4 秒旋轉一圈 |
| 答對 | 翡翠綠完整圓圈 | 3 秒呼吸 |

請注意與討論會持續顯示音量情境，不會因語音閒置倒數自動回待機。提問預設顯示 10 秒，答對與答錯各顯示 5 秒，結束後返回原基礎模式；休息預設 600 秒，再以 20 秒收尾提醒結束。手動切換基礎模式會取消當前暫時回應。柔和燈光只提示全班活動節奏，不評分或標記個別學生。

## 6. 噪音量測與離線語音指令

同一條電腦麥克風收音供音量分析與語音辨識使用。噪音分級只依實際音量，不判斷人聲或環境音；Silero VAD 僅用於語音指令的斷句。語音可以在句中辨識短指令，句尾仍保留完整片段的補辨。

噪音仍須達到各模式的音量門檻及持續時間才會切換。語音模型未就緒時，介面會提示，音量量測仍持續。單一麥克風無法辨別發言者或分離同時發生的聲音。

按課堂頁的「開啟語音」使用本機 SenseVoiceSmall INT8 與 Silero VAD。首次載入完成、顯示就緒後再說指令。可直接說 `standby／待機`、`notice／注意`、`discussion／討論`、`rest／休息`、`question／提問`、`correct／答對`、`wrong／答錯`。完整句子也可觸發，例如 “one two three question” 或 “you are wrong”。英文以完整單字邊界比對，`questionnaire` 不會誤觸 `question`。每次辨識片段若有多個指令，採用最後一個完整觸發詞；相同位置優先較長別名。重複命令有約 2 秒冷卻，手動操作優先。

說 `no sensor` 或「關閉語音」會暫停模式語音指令，噪音偵測仍運作；系統會保留啟動詞的辨識，因此可再說 `sensor on` 或「啟動語音」恢復。每個基礎情境按鈕內有獨立的 MP3 與語音開關；語音開關決定該情境的語音指令是否可觸發，左側的語音總開關仍須開啟。提問、答對、答錯的語音指令不受四情境開關影響。

可在「計時」旁的「手機控制」頁按「顯示手機網址」，手機與電腦連至同一 Wi-Fi 後，用手機瀏覽器開啟顯示的網址。手機只有七個模式按鈕，不使用手機麥克風；電腦持續負責噪音與語音偵測。手機連線且勾選「啟動手機控制」時，四個基礎情境才改由手機按鈕切換，桌面語音仍可切換三種互動；未勾選或手機斷線時，四情境語音依各自開關運作。若網址無法連線，確認 Windows 防火牆允許此程式在私人網路接收連線，且 Wi-Fi 未隔離裝置。

在「自訂語音指令」以逗號分隔別名；新增短詞前，確認它不常出現在一般講課內容。若辨識成固定錯字，可在「辨識修正」逐行輸入「誤辨文字＝觸發詞」，例如 `questions＝question`。修正是明確文字替換，不會模糊猜測；儲存前確認結果不會意外匹配其他指令。觸發詞與辨識修正同樣按收音區標題右側的「儲存設定」保存。

連續說話時，每 250 ms 提交最多 1.2 秒的上下文辨識；不必等滿整個視窗，累積至少 320 ms 音訊且偵測到語音便可開始。另保留結尾靜音約 320 ms、最長 4 秒分段的完整補辨，已觸發的指令不會因補辨再觸發。待辨識佇列只保留最新片段，手動操作前、停止收音前及斷線前的過期結果會丟棄。

先前的本地固定音訊測試，短視窗 CPU 解碼約 59–86 ms；完整收音與辨識佇列的英文回放測得目標詞音訊結束後約 **0.47 秒**觸發。這是特定樣本的結果，不代表所有真人語音或其他電腦都相同。口音、距離、背景音、CPU 負載及切詞仍會影響速度與準確率。建議自訂短而明確的觸發詞，避免過長句子。這些本地語音測試素材未隨公開版本提供；公開測試會明確標示跳過素材回放。

## 7. 五項課堂計時

「計時」頁包含五項設定，按該頁的「儲存計時」後，下一次啟動對應模式時套用：

| 計時 | 預設值 | 用途 |
|---|---:|---|
| 提問 | 10 秒 | 提問暫時回應 |
| 答對／答錯 | 5 秒 | 答案回饋暫時回應 |
| 休息 | 600 秒 | 休息倒數 |
| 休息收尾 | 20 秒 | 返回課堂前的提醒 |
| 語音閒置 | 0 秒 | 0 代表停用閒置回待機 |

語音閒置只作用於適用的語音控制狀態；請注意與討論會持續運作，不受閒置計時影響。所有數字輸入請用鍵盤修改，勿用滑鼠滾輪更動參數。

## 8. 自訂音源與隨音樂波動

「連線與收音」的「自訂音源」可為七個模式及休息收尾各自選擇、試聽或清除 MP3／WAV，並設定播放音量與淡入淡出。套件附帶原提供者指定的《藍色多瑙河》MP3，首次設定時作為休息預設曲；休息收尾音源可另行設定，未設定時不播放。各模式的音檔播放完畢會循環，直到模式結束或手動停止播放；四個基礎情境另可用按鈕內的 MP3 開關決定是否播放。自訂音檔會複製至使用者資料夾，移動原始檔案不影響已匯入的音源。選檔、清除及波動勾選會立即保存；音量與淡入淡出則按標題右側「儲存音源設定」。清除預設曲後不會每次啟動自動加回。

《藍色多瑙河》音源由專案提供者提供並指定一併發布，來源為 [女神来了的 YouTube 影片](https://www.youtube.com/watch?v=32fMNpLsvRY)，影片描述標示「Blue Danube by Sergey Pervov」，套件檔名為 `audio/blue-danube.mp3`。這份錄音不屬於本專案的 MIT 授權，權利仍歸原權利人；YouTube 來源註記本身不是錄音再授權文件，目前未提供可核實的錄音散佈授權。若要另外公開使用或轉授權該錄音，需確認錄音權利；可改用附帶的 MIT 原創示範曲 `audio/default-rest.mp3`。

「隨音樂波動」可逐模式開啟。播放時依實際解碼音量平滑調整整體亮度，不改變該模式圖案、顏色或動畫；停止、取消勾選或沒有有效音訊時回到原模式畫面，亮度不超過 30%。它不是頻譜圖，也不會另開麥克風。環境噪音只依麥克風音量分類，不排除人聲；注意與討論音樂會循環播放，依平穩、漸活躍、活躍級數提高音量，最高不超過「播放設定」音量。除休息倒數外，麥克風收音與噪音分析會持續運作，不因音樂播放或提問／答對／答錯提示音而暫停；程式會補償注意與討論循環音樂的喇叭回授，外部噪音仍會照常偵測。語音指令另以斷句 VAD 辨識。音源播放設定請用「儲存音源設定」保存。

本版加強亮暗起伏，安靜段落會明顯變暗，有聲段落平順亮起，保留短暫上升與較慢下降的平滑處理。《藍色多瑙河》固定片段、50% 播放音量的 PCM 比對中，亮度起伏跨度約為前版 3.56 倍；這是同一份解碼音訊的算法比較，並非實板感知測試。音檔本身的動態和播放音量仍會影響效果，靜音或無聲段落不會產生假的音樂波動。

## 9. 建議操作流程與排查

建議流程：確認 WLED 與麥克風狀態 → 選定麥克風並安靜校準 → 選擇「請注意」或「討論」→ 視需要啟動語音 → 依課堂活動手動切換休息、提問或回饋。課前先用短指令確認語音，並實際觀察安靜與交談時的相對音量，再逐步調整門檻。

若燈效太敏感或反應太慢，先檢查即時 dBFS、基線、麥克風距離及系統增益，再依第 4 節每次調整約 2 dB。校準失敗時先減少背景聲並檢查收音；更換裝置或輸入增益後重新校準。若語音未命中，確認語音已開啟、麥克風正常、觸發詞完整，並查看最近辨識文字；可先手動切換，之後再修正別名或確定的錯字。

燈光作為友善的全班節奏提示：先向學生說明它不是個人評分或監控。若要了解接受度，可簡短比較相近課堂活動是否使用柔和燈光，課後匿名詢問是否舒服、是否看懂活動變化，以及是否感到被警告或監控；尊重負面回饋，避免把音量降低當成學生接受的證明。目前沒有可宣稱的學生接受度結果。

## 10. 設定、隱私與支援範圍

Windows 的設定、匯入音源與活動紀錄位於 `%APPDATA%\Responsive Classroom`。設定使用 UTF-8、原子儲存，升級遷移前先備份；自訂計時、音源、觸發詞、安靜基線與板子方向會保留。本版只調整仍完整等於前版預設、且不與自訂注意門檻衝突的討論門檻。活動紀錄可包含狀態、音量和已接受指令，不保存原始錄音；若不需要紀錄，可在設定 JSON 將 `session_logging_enabled` 設為 `false`。語音模型離線執行，錄音不傳送到雲端。

v3.1.2 會從噪音量測中扣除與「注意／討論」循環音樂同步的喇叭回授；麥克風與語音辨識仍持續收音，播放期間的外部噪音也會照常偵測。發佈流程只建置及驗證 Windows x64 ZIP，Mac 版本不再維護。乾淨 Windows VM、其他電腦的實體麥克風、教室喇叭及燈板仍需實機驗收。若沒有輸入音量，檢查 Windows 麥克風隱私權、系統靜音與所選輸入裝置；確認即時音量後重新校準。遇到燈板連線問題，確認 WLED 已上網、電腦與燈板位於可互通網段，再嘗試手動 IP 或本機網段搜尋。遇到視覺方向問題，核對單一燈板的方向與蛇形排列設定。

## 11. 開發環境與專案結構

開發環境名稱為 `responsive_classroom`，固定使用 Python 3.12；直接依賴版本列在 `source/requirements.txt`，開發檢查工具列在 `source/requirements-dev.txt`。可攜套件已包含執行環境，只有修改原始碼的組員需要安裝 Python。

| 位置 | 用途 |
|---|---|
| `source/classroom_core.py` | 設定、狀態、計時與 PatternMapper；Controller 是唯一狀態管理者 |
| `source/classroom_service.py` | Web Channel、背景任務與服務協調 |
| `source/classroom_audio.py` | 共用收音、噪音分級、VAD、SenseVoice 與指令解析 |
| `source/classroom_hardware.py` | WLED 裝置、JSON 狀態與即時像素輸出 |
| `source/pattern_renderer.py` | 共用像素畫面與平滑過渡 |
| `source/classroom_playback.py` | 音源匯入、播放、淡入淡出與音樂亮度波動 |
| `source/resources/web/` | 本機 Web UI；沒有對外開放的網頁控制伺服器 |
| `source/tests/`、`source/tools/` | 自動測試、環境準備、模型驗證與封裝 |
| `.devcontainer/`、`.github/workflows/` | Codespaces 環境及 GitHub 自動驗證／發佈 |

在終端進入 Git clone 後的專案目錄，執行：

```powershell
git clone https://github.com/tput600/responsive_classroom.git
cd responsive_classroom
py -3.12 source/tools/setup_environment.py --dev --models
.venv/Scripts/python.exe source/classroom_app.py
```

第一次準備需要網際網路下載依賴及模型。模型來源、授權與 SHA-256 固定在 repository；下載或雜湊失敗時會停止，不覆寫有效模型。模型二進位不存入 Git，完整 Release 則包含模型供離線使用。macOS 版本已停止維護，本版不提供 Mac 套件。

## 12. 本地與雲端共同修改

本地與 GitHub 使用相同的 `main` 分支；公開歷史從乾淨版本開始，不含原提供者的私人測試歷史。私人設定、音源、執行紀錄、`.codex/`、`.venv/`、封裝輸出都留在本地並受 `.gitignore` 排除。不要使用 `git add -f` 將它們加入公開版本。

一般修改流程：

```powershell
git pull --ff-only
git switch -c feature/my-change
# 修改 source 下的程式或 README
.venv/Scripts/python.exe -m unittest discover -s source/tests -t source -v
git add source README.md README.en.md
.venv/Scripts/python.exe source/tools/check_public_tree.py
git diff --cached
git commit -m "Describe the change"
git push -u origin feature/my-change
```

在 GitHub 開 Pull Request，Windows 自動檢查通過後合併回 `main`；本地再 `git switch main`、`git pull --ff-only`。只有一位維護者時也可測試後直接 commit／push `main`。若 `pull --ff-only` 提示分歧，先整理自己的分支再合併；不要強制推送覆蓋他人修改。

在 GitHub 按 **Code → Codespaces → Create codespace**，環境會準備固定依賴與離線模型，可修改 UI、核心與演算法，再 commit／push 至 GitHub，由 Windows 自動驗證。Codespaces 不能直接存取使用者電腦的麥克風或教室區域網路燈板；實際收音、音效及燈板驗收需在本地進行。雲端變更 commit／push 後，本地 pull 即可同步。

## 13. 發佈新版本與檢查

用 **Build Windows desktop candidate** 建置及驗證 Windows x64 ZIP，再從 `main` 手動執行 **Publish Windows desktop release**。發布流程要求 main 與成功建置的 commit 完全一致，並再次檢查 ZIP、校驗碼、Windows 資源清單及遠端資產雜湊。推送 main 不會自動發布，也不會覆蓋既有版本。

更新 `source/classroom_resources.py` 的 `VERSION` 及中英文手冊版本，完成測試後，在 Windows 開發環境執行：

```powershell
.venv/Scripts/python.exe source/tools/build_release.py
```

它會檢查公開檔案、驗證模型、執行單元測試、封裝 runtime，並在中文及空白路徑、移除開發 PATH 的環境短測凍結後的模型、Web UI、計時、滾輪防誤觸與 MP3 解碼，最後產生 `artifacts/` 下的完整 ZIP、SHA-256 和資源 manifest。這些驗證不等於乾淨 Windows VM 或實板驗收；測試詳細結果保留在 `build/reports/`，不會上傳私人執行資料。

也可在 GitHub **Actions → Build Windows release → Run workflow**，輸入與 VERSION 相符的 `v版本號`。它使用 GitHub environment `responsive_classroom`，不需保存個人的 GitHub token；成功才建立 Release。版本已存在時不會默默覆蓋，應改用新版本號。

自動驗證包含語法錯誤、Bandit 安全規則、pip-audit 已知依賴漏洞及公開檔案檢查。模型雜湊驗證可偵測損壞；私人 IP、MAC、絕對使用者路徑、金鑰、活動紀錄不能加入公開內容。這些掃描不能證明零漏洞，Qt／原生 DLL 仍需隨上游安全更新重建。
